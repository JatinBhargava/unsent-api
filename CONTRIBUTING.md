# Contributing to Unsent API

Thanks for taking the time to contribute to **Unsent API** 🎉  
This guide explains how to contribute code, follow naming conventions, and keep the project consistent.

---

## 📌 Getting Started

1. Fork the repository
2. Clone your fork locally
3. Create a new branch from `develop`
4. Make your changes
5. Open a Pull Request

---

## 🌿 Branch Naming Rules

Branches must follow this format:

type/short-description

### Allowed branch types
- feature
- bugfix
- hotfix
- refactor
- docs
- chore

### Examples
- feature/user-authentication
- bugfix/null-pointer-login
- docs/update-readme


---

## 📝 Commit Message Rules

We follow a simple and consistent commit message format:

type: short description

### Allowed Commit Types
- feat — new features or functionality
- fix — bug fixes
- test — adding or updating tests
- docs — documentation-only changes
- refactor — code changes that neither fix a bug nor add a feature
- chore — maintenance tasks (builds, configs, tooling, cleanup)

### Examples
- feat: add diary creation endpoint
- fix: handle null user in service
- test: add repository tests
- docs: update local setup guide
- chore: update Maven dependencies
